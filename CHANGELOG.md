# Changelog

## Не выпущено

### Добавлено

- **Справочники awg / sing-box / mihomo сверены с апстримами** (skill'ы для
  агентов). AWG: описано поколение **AWG 3+** ветки `amneziawg-go v3.x`
  (`HeaderProtectionKey` — требует `S1–S4` ≥ 12, `ContentPaddingAddition`,
  тайминги `Rekey*/RejectAfterTime/KeepaliveTimeout/MaxHandshakeAttempts`,
  тип `range` у `PersistentKeepalive`), деление параметров на client-side и
  server-side, настоящий синтаксис `I1..I5` (теги `<b>/<r>/<rd>/<rc>/<t>`, а
  не «просто hex»), поле `[Peer] AdvancedSecurity` и **смена каталога
  UAPI-сокета на `/var/run/amneziawg/`** — с пометкой, что наш код всё ещё
  знает только старый `/var/run/wireguard/`. mihomo: новый раздел про
  `sniffer` (дефолты из `config/config.go` v1.19.29 и почему при fake-ip
  нужен `override-destination: false`), дефолтное имя TUN `Meta` из
  `listener/sing_tun/server.go`, раздел про наши генераторы конфигов
  маршрутизации, полный список эндпоинтов API. sing-box: линия поднята до
  **v1.13.16**, добавлен разбор новинок 1.14 (`sing-box schema` и `$schema`,
  исправленная семантика rule-set, параллельные DNS-ответы, endpoint'ы
  OpenVPN/OpenConnect, network namespaces, UDP-NAT, отказ AnyTLS слать
  клиентские метаданные) и предупреждение о порядке `{"action":"sniff"}`
  относительно доменных правил. `docs/upstream.json` перевыверен
  (`tools/check_upstream.py --offline` — зелёный)
- **Скилы проекта доступны любым AI-агентам, а не только Claude** — новый
  `tools/gen_agent_index.py` собирает индекс справочников из frontmatter
  `.claude/skills/*/SKILL.md` и раскладывает его по кросс-инструментальным
  точкам входа: `AGENTS.md` (стандарт для Codex, Cursor, Jules, Aider,
  Zed), `GEMINI.md`, `.github/copilot-instructions.md`,
  `.cursor/rules/zapret-gui.mdc` и машиночитаемый `docs/skills.json`.
  Раньше каталог `.claude/` находил только Claude Code, и остальные
  агенты правили подсистемы вслепую. Дублируется список скилов, а не их
  содержимое: единственный файл с содержательным текстом — `AGENTS.md`,
  остальные ведут на него. Синхронность стережёт
  `tests/test_agent_skill_index.py`
- **Редактор стратегий знает рантайм-флаги nfqws2** — `--qnum`, `--debug`,
  `--user`, `--uid`, `--daemon`, `--pidfile`, `--chdir`, `--intercept`,
  `--dry-run`, `--version` (`web/js/utils/nfqws2_spec.js`). Их подставляет
  сам GUI, но пользователь копирует готовую команду из «Превью» или
  мануала — и линтер ругался «неизвестный флаг» на полностью валидной
  строке
- **Удаление движков Telegram прямо из GUI** (issue #272) — кнопки
  «Удалить» у обеих панелей и `POST /api/tgproxy/uninstall`
  (`engine=tgwsproxy|mtproto`). Раньше поставленный из GUI движок
  удалялся только по SSH. Перед удалением прокси останавливается —
  иначе остался бы процесс без файлов и занятый порт; неудача остановки
  удалению не мешает (движок мог быть и не запущен), но её текст
  показывается. Пакетные движки удаляются пакетным менеджером, а не
  `rm` бинарника, иначе база пакетов продолжила бы считать их
  установленными (`api/tgproxy.py`, `web/js/pages/tgproxy.js`)
- **Резервный движок Telegram наконец получает трафик** — новый
  `core/tgproxy_redirect.py` заворачивает TCP к CIDR датацентров
  Telegram на порт `tg-mtproxy-client` правилом REDIRECT (nft или
  iptables — тем же выбором, что и основной firewall). Раньше таких
  правил не ставил никто, а движок работает только по
  `SO_ORIGINAL_DST`, то есть не получал ни одного соединения. Правила
  ставятся после успешного старта и снимаются при любой остановке —
  в том числе если процесс умер сам: оставленные, они увели бы весь
  Telegram на порт, который никто не слушает. Хуки PREROUTING (клиенты
  за роутером) и OUTPUT (сам роутер), своя цепочка/таблица, повторный
  запуск не копит дубли, ошибка на любом CIDR откатывает всё.
  Состояние перехвата видно на странице. Режим «через WARP-туннель» и
  резервный движок теперь взаимоисключающи явно: REDIRECT перехватывает
  пакеты раньше маршрутизации, поэтому включить оба сразу нельзя.
  (`core/tgproxy_redirect.py`, `core/tgproxy_manager.py`,
  `web/js/pages/tgproxy.js`)
- **Резервный движок Telegram работает «из коробки»** — релей и ключ
  публичного релея заданы по умолчанию (`MTPROXY_DEFAULT_RELAY`,
  `MTPROXY_DEFAULT_TUNNEL_SECRET` в `core/tgproxy_manager.py`), а свои
  задаются в GUI: новый `POST /api/tgproxy/mtproto/config` и поля
  «Relay» / «Secret релея» на странице. Пустое значение означает «взять
  дефолт» и намеренно не записывается в конфиг при запуске — иначе
  смена дефолта в коде не доехала бы до роутера. Ключ держим настройкой,
  а не зашиваем в бинарник: сменить его — правка конфига, а не
  пересборка. Откуда он взят и как обновить, когда владелец релея его
  ротирует, — в комментарии у константы и в
  `.claude/skills/telegram-tunnel/SKILL.md` §10.3.
- **Свои сборки opera-proxy и tg-mtproxy-client** — по образцу usque
  (`build-opera-binaries.yml`, `build-tgproto-binaries.yml`), обе под
  mipsel/mips/aarch64/armv7/x86_64 с проверкой sha256 по `manifest.json`
  релиза. Мотивы разные:
  - у **opera-proxy** стоял `allow_unpinned` (апстрим релизится раз в
    1–2 недели, ставится последний релиз), а закреплённый sha256
    относился к более старой версии — на практике почти каждая
    установка шла **без сверки хэша**, если апстрим не публиковал
    контрольные суммы. Теперь проверка снова строгая, а «последняя
    версия» сохранена;
  - у **tg-mtproxy-client** в релизах апстрима **нет aarch64 и armv7** —
    на массовых aarch64-Keenetic резервный движок Telegram было не
    поставить вообще; вдобавок ассеты лежат под rolling-тэгом и могут
    перезаливаться, из-за чего закреплённые sha256 протухают. Секрет
    туннеля в нашу сборку не зашивается и не нужен: менеджер и так
    передаёт `--tunnel-url`/`--tunnel-secret` явно.

  У обоих прежний источник сохранён запасным. «Обновления» теперь
  показывают версию нашей сборки — ту, которую реально поставит кнопка
  «Установить», — и уходят к апстриму, только пока сборки нет.
  (`core/ext_binary_installer.py`, `core/update_checker.py`)
- **Свои сборки usque** — `.github/workflows/build-usque-binaries.yml`
  кросс-компилирует апстрим `Diniboy1123/usque` под
  mipsel/mips/aarch64/armv7/**x86_64** и публикует релизы
  `usque-bin-v<версия>` (по образцу awg/sing-box). Раньше бинарник брался
  из стороннего `.ipk` `usque-keenetic`, который отставал от самого usque
  (в v0.3.0 лежал 4.2.0, когда апстрим выпустил 4.2.1), **не содержал
  x86_64** (на Linux-ПК/VPS usque было не поставить вообще) и требовал
  opkg/apk. sha256 берётся из `manifest.json` релиза — хэш сборки
  известен только после неё, но проверка осталась обязательной и
  fail-closed. Прежний `.ipk` остался запасным источником: он
  используется, если нашей сборки под эту архитектуру нет (в том числе
  до публикации первого `usque-bin-*`). Заодно это убрало путаницу
  версий: тег нашей сборки кодирует версию самого usque, поэтому
  «установлено» и «в релизе» — наконец одна величина.
  (`.github/workflows/build-usque-binaries.yml`,
  `core/ext_binary_installer.py`, `api/usque.py`,
  `web/js/pages/usque_setup.js`)
- **Файл `LICENSE`** (MIT) — его не было, из-за чего GitHub не мог

- **WARP/MASQUE: регистрация через уже работающий обход.** Там, где
  провайдер режет сам `api.cloudflareclient.com`, прямая регистрация
  падает с `TLS handshake timeout` и получить сессию было неоткуда
  (собрать её из AWG-конфига нельзя — другой протокол и другие ключи). В
  окне регистрации появился выбор «Регистрировать через» с тем же
  списком, что и «Качать через»: `direct`, `awg:<iface>`,
  `singbox:<name>`, `mihomo:<name>`. Опирается на то, что `usque
  register` ходит через `http.DefaultClient` с
  `Proxy=http.ProxyFromEnvironment`, то есть уважает `HTTPS_PROXY`
  (проверено на реальном бинарнике). Для sing-box/mihomo передаётся их
  локальный прокси; у AWG порта нет, поэтому на время регистрации
  поднимается эфемерный SOCKS5 на loopback, чьи исходящие соединения
  привязаны к интерфейсу через `SO_BINDTODEVICE` — без единой правки
  маршрутов и firewall. Мост открыт только на хост регистрации и
  умирает вместе с операцией. (`core/iface_socks.py`,
  `core/usque_manager.py`, `api/usque.py`, `web/js/pages/usque.js`)

### Исправлено (движок)

- **После перезагрузки роутера GUI показывал «nfqws2 не работает» при живом
  обходе** (discussion #102). Обход поднимает автозапуск `S99zapret` —
  своим `--daemon --pidfile=/var/run/zapret-nfqws.pid`. Менеджер же считал
  запущенным только то, что видел через свой `Popen` или свой PID-файл
  `/var/run/zapret-gui-nfqws.pid`, а `/var/run` — tmpfs: после ребута его
  нет в принципе. В итоге видео игралось, а «Главное» и «Управление»
  рисовали остановленный обход, и «Стоп» выглядел бесполезным. Теперь
  менеджер подбирает чужой процесс: сначала PID-файл автозапуска, затем
  скан `/proc` — но только по демонам (`--daemon`/`--pidfile` в cmdline),
  чтобы не принять за обход короткоживущие `nfqws2`, которые крутит под
  собой `blockcheck2.sh` во время подбора стратегии. Скан троттлится (раз в
  2 с), подобранный процесс помечен в статусе (`external`) и подписан в
  UI как «запущен автозапуском» — иначе непонятно, откуда uptime больше
  времени жизни самой сессии GUI (`core/nfqws_manager.py`,
  `web/js/pages/{dashboard,control}.js`)

- **Подбор стратегий оставлял обход выключенным, если до него nfqws2 работал
  с автозапуска** — сканер сохраняет состояние через `get_last_args()`, а у
  подобранного процесса «последних аргументов» нет, и восстановление
  поднимало голый `nfqws2` без десинка. Теперь при пустых аргументах
  пересобирается активная стратегия — ровно то же, что делает кнопка
  «Старт». Общий хелпер переехал в `core/strategy_builder.active_strategy_args()`
  (`core/strategy_scanner.py`, `api/control.py`)

- **«Обновления» предлагали обновить неустановленные sing-box и mihomo**
  (discussion #102) — `has_update` считался как «в релизе есть версия И она
  не равна установленной», а у отсутствующего бинарника версия пустая, так
  что неравенство выполнялось всегда. В таблице горело «← доступно» с
  кнопкой «Обновить» для того, чего на роутере нет. Свои страницы движков
  этим не страдали: `SetupUI` считает `has_update` сам и гейтит по
  `installed`. Починено в обоих инсталляторах, плюс общий гейт в
  `check_all()` — чтобы следующая такая забывчивость не доехала до
  страницы. Заодно строка usque показывает в подсказке путь, по которому
  найден бинарник: «Установлен: Да» там означает ровно «в стандартном
  каталоге лежит исполняемый файл usque» (`core/singbox_installer.py`,
  `core/mihomo_installer.py`, `core/update_checker.py`,
  `web/js/pages/update_checker.js`)

- **Кнопки «Копировать» не работали на роутере** (issue #272) —
  `navigator.clipboard` существует только в secure context (https или
  localhost), а GUI открывают по обычному http на LAN-адресе
  (`http://192.168.1.1:1080`). Там объект отсутствует целиком, и вызов
  `navigator.clipboard.writeText(x).then(ok, err)` падает с TypeError
  **синхронно** — не срабатывал даже обработчик ошибки, кнопка молча не
  делала ничего. Так ломались ссылка `tg://proxy`, hex блоба и «Копировать
  команду» в превью стратегии: у первых двух фолбэка не было вовсе, у
  третьего он был в `.catch()`, куда исполнение не доходило. Новый
  `web/js/utils/clipboard.js` пробует Clipboard API, затем
  `execCommand`-фолбэк (он-то и работает по http), а если не вышло и это —
  выделяет текст и подсказывает Ctrl+C. Заодно убраны шесть копий
  самодельного фолбэка, разъехавшихся по страницам

- **Движок Telegram не устанавливался** — `BINARIES["tgwsproxy"]` ходил в
  `/releases/latest` апстрима `spatiumstas/tg-ws-proxy-go`, а тот в
  **v1.0.0 переписан с Go на Python и превращён в десктопное GUI-приложение**
  (сборки PyInstaller под Windows/macOS/Linux). Пакетов для роутера там
  больше нет: в `0.9.3` их упаковки 52 файла, начиная с `v1.0.0` — ноль, и
  релизы несут `.exe` вместо `tg-ws-proxy_<ver>_entware_<arch>.ipk`.
  Установка не находила ни точного имени ассета, ни версионно-независимого
  суффикса и падала на 404. Тег закреплён на `0.9.3` — последнем релизе с
  роутерными пакетами; показывать `v1.4.0` как «доступно обновление» тоже
  неверно, это программа для другой платформы
- **AmneziaWG: `J1..J3` и `Itime` роняли поднятие туннеля** — эти поля
  описаны в документации протокола 2.0, но парсера у них нет: `key_match` в
  `src/config.c` amneziawg-tools их не знает ни в одном релизе, включая
  свежий `v3.0.20260730`. На неизвестном ключе парсер делает `goto error` —
  печатает `Line unrecognized` и **отбрасывает весь конфиг**, так что
  импортированный из клиента Amnezia профиль просто не поднимался, а
  наружу было видно лишь невнятное «Unable to modify interface». Теперь
  поля по-прежнему разбираются и переживают round-trip (терять их при
  импорте нельзя), но в `awg setconf` не отдаются
- **Стратегия `discord_timestamp_travel` падала на каждом пакете** —
  `custom_funcs.lua` звал `bitright()`, функции с таким именем в nfqws2
  нет и не было (она называется `bitrshift`). В Lua это не ошибка
  загрузки, а «attempt to call a nil value» в рантайме: стратегия
  предлагалась пользователю из трёх каталогов (basic/advanced/direct) и
  тихо не работала. `--intercept=0` такое не ловит — он проверяет только
  `lua-init`. Теперь каждый вызов в наших lua-расширениях резолвится
  против определений бандла, C-функций nfqws2 и стандартной библиотеки
  (`tests/test_lua_symbols_resolve.py`), а список исключений
  самоочищающийся: отдельный тест падает, когда исключение стало
  ненужным, иначе allowlist со временем замаскировал бы новые опечатки

### Прочее из этого релиза
- **Перехват DNS (:53 → встроенный прокси) — доменные маршруты видят
  живые запросы клиентов без dnsmasq** (`core/routing/dns_intercept.py`,
  `api/routing.py`, `web/js/pages/routing_unified.js`, `app.py`; прямой
  запрос пользователя с Keenetic: «перенаправлять запросы на :53 на свой
  порт»). Без dnsmasq доменные правила ловили только IP, разрезолвленные
  самим роутером, — ротация CDN-поддоменов (rr3---sn-*.googlevideo.com)
  уходила мимо туннеля. Теперь opt-in кнопка «Включить DNS-перехват» на
  странице «Маршрутизация»: iptables nat PREROUTING (цепочка
  AWG_DNS_INT) заворачивает udp:53 LAN-клиентов (и адресованный роутеру,
  и hardcoded 8.8.8.8) во встроенный UDP-прокси (threading + queue —
  python3-light, без asyncio), который пересылает запрос штатному
  резолверу (ndnsproxy) и, разбирая ответ (A/AAAA, компрессия имён),
  кладёт IP доменов активных правил (suffix-match — поддомены
  покрываются) в ipset правила или policy-db iproute-пути. Запросы
  самого роутера идут через OUTPUT и не перехватываются — петли нет.
  Failsafe: REDIRECT ставится только при живом прокси и снимается при
  stop()/atexit/смерти цикла. Ограничение: клиенты с DoH перехвату не
  видны (как и у dnsmasq). Состояние восстанавливается после ребута
  (boot-hook), статистика (запросов/совпало/IP добавлено) — в UI и
  `GET /api/routing/dns-intercept`. Тесты — `test_dns_intercept.py`
  (парсер, harvest по бэкендам, живой UDP-прокси на loopback).
- **IP-списки zapret2 (ipset-*.txt) как назначение маршрута — `ipl:<имя>`**
  (`core/unified/model.py`, `web/js/pages/routing_unified.js`; отчёт с
  Keenetic: «без выбора устройства маршрутизация не работает»). Доменная
  маршрутизация без dnsmasq принципиально ограничена: роутер видит только
  IP, которые сам разрезолвил, а клиент ходит на ротацию CDN-поддоменов.
  Маршрут по CIDR-подсетям сервиса от DNS не зависит вовсе — и готовые
  списки подсетей (Discord, googlevideo, Cloudflare, Instagram, …) уже
  лежат в поставке для nfqws2 (`/opt/zapret2/ipset/ipset-*.txt`). Теперь
  они доступны и в маршрутизации: в редакторе маршрута рядом с
  nfqws2-хостлистами выбираются IP-списки (id `ipl:<имя>`),
  `Destination.resolve()` разворачивает их в CIDR через `ipset_manager`
  (кривые строки файла отфильтровываются, а не валят весь маршрут).
  Это рекомендуемый способ destination-only маршрута тяжёлых CDN-сервисов
  на Keenetic. Тесты — `test_unified_model.py`.
- **Routing doctor — пошаговая диагностика «правило есть, а трафик мимо»**
  (`core/routing/doctor.py`, `api/routing.py`). По каждому включённому
  правилу проверяется вся цепочка на живом устройстве: интерфейс поднят →
  default-route в таблице → ipset существует и наполнен → mark-правила в
  mangle стоят и **счётчики пакетов растут** → `ip rule fwmark` на месте →
  masquerade повешен → контрольный резолв домена → IP в set'е →
  `ip route get <ip> mark <mark>` ведёт в туннель. Первый ✗ в списке —
  место обрыва. CLI работает даже без bottle:
  `python3 -m core.routing.doctor` (`--json` — машиночитаемо), API —
  `GET /api/routing/doctor`. Тесты — `test_routing_doctor.py`.
- **apk-пакет для нового OpenWrt (24.10+/25.x) в релизах** (`Makefile`,
  `.github/workflows/release.yml`, `README.md`). Новые версии OpenWrt перешли
  с opkg (`.ipk`) на apk (`.apk`, формат APKv3), и старый `.ipk` там не
  ставится. Теперь релиз собирает **оба** формата:
  - `zapret-gui-openwrt.ipk` — для OpenWrt ≤ 23.05 (opkg), как раньше;
  - `zapret-gui-openwrt.apk` — для OpenWrt 24.10+/25.x
    (`apk add --allow-untrusted ./zapret-gui-openwrt.apk`).
  Совместимость со старыми OpenWrt, Keenetic/Entware (`.ipk`) и Linux
  (`.tar.gz`) полностью сохранена — добавлен только новый артефакт.
  `make openwrt-apk` собирает пакет той же командой `apk mkpkg`, что и штатная
  build-система OpenWrt (`include/package-pack.mk`): маппинг сопровождающих
  скриптов postinst→post-install, prerm→pre-deinstall, `arch:noarch`. В CI
  пакет собирается внутри `alpine:edge` (`apk.static` из apk-tools 3, файлы
  пакета — root:root).
- **Установка модулей ядра NFQUEUE для OpenWrt — прямо из GUI, без консоли**
  (`core/kmod_manager.py`, `api/diagnostics.py`, `web/js/pages/diagnostics.js`).
  На стоковом OpenWrt модуль `nfnetlink_queue` в прошивку не входит — без него
  nfqws2 не может открыть NFQUEUE и **завершается сразу после запуска
  (exit 1)**. Раньше пользователь видел только «exit code 1» и вынужден был
  сам гуглить имена пакетов И правильный менеджер. Теперь:
  - **Диагностика → Firewall** при недоступном NFQUEUE показывает блок починки
    с кнопкой «Установить модули NFQUEUE» — ставит нужные пакеты в фоне
    (`apk add`/`opkg install` + `modprobe`) и перепроверяет доступность, без
    перезагрузки, если получилось. Консоль не требуется.
  - Набор пакетов подбирается по firewall-бэкенду: iptables →
    `kmod-nfnetlink-queue`+`iptables-mod-nfqueue`, nftables →
    `kmod-nfnetlink-queue`+`kmod-nft-queue` (+`kmod-nf-conntrack`).
  - Детект **системного** пакетного менеджера учитывает переход OpenWrt 24.10+
    с opkg на **apk** и намеренно НЕ трогает Entware'ский `/opt/bin/opkg`
    (модули ядра оттуда не ставятся). Авто-установка предлагается ТОЛЬКО на
    настоящем OpenWrt; на Keenetic/Entware/ПК даётся текстовая инструкция
    (там kmod приходят из прошивки/ядра). Сервер повторно проверяет платформу
    перед установкой (POST → 409 на неподходящей).
  - `nfqws2` при мгновенном падении теперь называет вероятную причину и даёт
    команду/подсказку в лог (`core/nfqws_manager.py`), а диагностика предпосылок
    добавляет конкретную команду пакетного менеджера в hint
    (`core/diagnostics.py`, issue `nfqueue_missing`/`ipt_nfqueue_target_missing`).
  - `install.sh` теперь поддерживает **apk** на OpenWrt 24.10+ (детект apk/opkg,
    `apk add`/`apk del`/`apk update`) — установка/удаление GUI больше не
    ломается на apk-based прошивках. Тесты — `tests/test_kmod_manager.py`.
- **Авто-переподключение AWG теперь поднимает заново УПАВШИЙ интерфейс**
  (`core/awg_watchdog.py`). Раньше watchdog следил только за «живыми»
  туннелями (протухший handshake / rx-stall / проба) и игнорировал
  упавшие: если демон/интерфейс умирал целиком, в `list_interfaces` его
  уже не было, и watchdog его «забывал». Теперь при включённом
  авто-переподключении watchdog на каждом тике проверяет и
  **autostart**-туннели (те, что должны быть подняты): если такой лежит —
  поднимает заново (`mgr.up`). Гейтится именно autostart-флагом, чтобы НЕ
  воскрешать туннели, остановленные пользователем вручную; cooldown и
  rate-limit — общие с рестартами (не уходит в цикл). Тесты —
  `test_awg_watchdog.py::TestResurrectDownAutostart`.
- **Авто-переподключение AWG теперь действительно срабатывает на «зависшем»
  туннеле** (`core/awg_watchdog.py`). Раньше при включённой галке «Переподключать
  при плохом соединении» туннель мог часами висеть «интерфейс поднят, а сайты не
  открываются» — ни один из детекторов не срабатывал. Закрыты два тихих
  blind-spot'а:
  - **Активная проба больше не врёт «жив» по WAN.** Проба — TCP-коннект через
    туннель (`SO_BINDTODEVICE`). Если привязка к интерфейсу не применялась (нет
    root / особенности роутера), старый код молча глотал ошибку и коннектился
    мимо туннеля по обычному WAN — проба всегда возвращала «жив», и watchdog
    НИКОГДА не перезапускал зависший туннель. Теперь привязка **проверяется**
    через `getsockopt(SO_BINDTODEVICE)`; не удалось подтвердить — проба честно
    «недостоверна» (не трактуется ни как успех, ни как провал), watchdog
    опирается на пассивные детекторы и один раз пишет об этом в лог. Заодно
    проба теперь IPv6-aware (для v6-хоста берёт `AF_INET6`, а не падает молча).
  - **Пассивный детектор «приём встал» больше не сбивается keepalive'ом.**
    Раньше он сбрасывал отсчёт на ЛЮБОЙ прирост `rx`, а WireGuard в ответ на
    принятый пакет шлёт пассивный keepalive (~32 Б / 10 с) — этой «капли» хватало,
    чтобы таймер застоя сбрасывался вечно и детектор не срабатывал никогда.
    Теперь «живым приёмом» считается только прирост выше порога
    `rx_stall_min_rx_bytes` (по умолчанию 1 КБ — заведомо выше keepalive-шума и
    ниже скорости любого реального соединения), накопительно от базовой точки.
  Плюс наблюдаемость: исход активной пробы по интерфейсам (`ok`/`fail`/
  `cant_bind`/`off`) виден в `GET /api/awg/watchdog` и на дашборде под галкой —
  сразу видно, идёт ли проба через туннель или работает только пассивная защита.
  Тесты — `test_awg_watchdog.py::{TestEvalRxStallMinRx,TestProbeTriState,
  TestMaybeRestartProbeTriState}`.
- **PersistentKeepalive = 25 проставляется новым AWG-конфигам автоматически**
  (`core/awg_config.ensure_persistent_keepalive`, вызывается в
  `AwgManager.save_config`). Покрывает все пути создания/импорта (ручной
  ввод, генерация WARP, импорт WARP-/подписочных конфигов). Без keepalive
  NAT-binding протухает за ~30–120с простоя и туннель «молча отваливается»
  (особенно за CGNAT / на мобильном). Явно заданное значение (в т.ч. `0` =
  выкл.) не трогаем; raw-текст без keepalive перерендеривается, с
  keepalive — сохраняется как есть. Тесты — `test_awg_config.py::
  TestEnsurePersistentKeepalive`, `test_awg_manager_lifecycle.py`.
- **geosite/geoip-маршрутизация теперь работает и для AWG-туннелей**
  (единый слой, `core/unified` + `core/routing/domain_rule.py`). Раньше
  geosite/geoip в маршруте применялись ТОЛЬКО на движках (sing-box нативно
  через geo-правила); для AWG (и mihomo) они молча пропускались с
  сообщением «работают только с движком». Теперь для нетуннельных-движков:
  - **geosite → домены** через тот же dnsmasq + ipset/nftset путь, что и
    обычные доменные правила (резолв набивает set, трафик маркируется и
    уходит в туннель);
  - **geoip → CIDR в nftables interval-set** одним mark-правилом
    (`ip daddr @set`) — БЕЗ тысяч отдельных `ip rule` (geoip:ru ≈ 22k
    сетей легли бы намертво в policy-db). На системах без nft (ipset
    hash:ip не хранит сети) geoip-CIDR в iproute-фолбэке капятся
    (`_IPROUTE_GEOIP_MAX`) с предупреждением.
  Проверено сквозь живой AWG-туннель: и geosite-домен, и geoip-CIDR
  заворачивают трафик в туннель (LAN-клиент виден сервером под tunnel-IP).
  sing-box по-прежнему использует нативный geo-движок (не дублируем).
  Тесты: `test_unified_applier` (folding), `test_routing_domain_iproute`
  (`TestGeoExpansionAndStaticCidrs`).
- **Скачивание nfqws2 и обновлений zapret-gui через средство обхода +
  выбор версии** (по аналогии с sing-box / AmneziaWG / mihomo). Раньше и
  движок nfqws2 (bol-van/zapret2), и сам веб-интерфейс качались только
  напрямую и только последней версией — а у целевой аудитории GitHub
  часто заблокирован, и обновиться было нечем, кроме как поднять обход
  заранее «руками». Теперь на странице **Управление zapret2**:
  - **Транспорт скачивания** — селект «Качать через»: напрямую, либо
    через уже поднятый AWG-интерфейс / sing-box / mihomo (тот же общий
    список `GET /api/install/transports`, что у остальных установщиков).
    Скачивание релиза и обращение к GitHub API идут через выбранный
    туннель/прокси; при явном транспорте прямой wget/curl-фолбэк
    отключён (иначе обход терял бы смысл).
  - **Выбор версии** — «последняя по умолчанию», либо любая из списка
    релизов (`GET /api/zapret/releases`, `GET /api/gui/releases`).
    Позволяет поставить конкретную/прежнюю версию (откат) и
    переустановить текущую.
  - Бэкенд: `core/zapret_installer` — `list_releases()` / `get_release(tag)`
    + `install(tag, transport)` / `update(tag, transport)`;
    `core/gui_updater` — `list_releases()` + `update(tag, branch,
    transport)` (по умолчанию тянет архив последнего релиза `vX.Y.Z`, с
    фолбэком на ветку `main`, если GitHub недоступен). Загрузки
    делегированы `core/binary_installer.download_file` (зеркало,
    оффлайн `file://`, транспорт, retry).
  - UI собран на общем под-компоненте `InstallExtras` (`setup_ui.js`) —
    та же «версия + транспорт», что в установке sing-box/mihomo/AWG.
- **Bottle встроен в проект (`vendor/bottle.py`)** — установка больше не
  требует сети для зависимостей. Раньше install.sh/postinst тянули bottle
  каскадом opkg → pip (PyPI) → raw.githubusercontent/jsdelivr (причём

### Изменено
- **`other.txt` больше НЕ подставляется автоматически (во всех режимах).**
  Раньше `filter.mode=hostlist` (дефолт) тихо подмешивал `--hostlist=other.txt`
  в каждый профиль без своего списка — и стратегия применялась ТОЛЬКО к доменам
  из `other.txt` (где обычно нет youtube/discord), а бесхостовые UDP-профили
  (Discord voice/STUN) вообще не выбирались (hostlist требует hostname). Теперь:
  - дефолтный `filter.mode` = **`none`**: стратегия применяется ко **всему
    трафику** на своих портах (`--filter-*`), circular подбирает приём
    per-домен. `hostlist` оставлен как алиас `none` (совместимость конфигов).
  - сужение списком — **по желанию пользователя**: добавить
    `--hostlist=`/`--hostlist-domains=` прямо в стратегию. В редакторе это
    **подсказка-INFO**, а не ошибка (`web/js/utils/nfqws2_lint.js`).
  - предохранитель **`filter.protect_excluded`** (новый, по умолчанию `true`):
    exclude `netrogat.txt` (банки/госуслуги/vk и т.п.) применяется во всех
    режимах кроме ipset — чтобы десинк не сломал критичные сервисы. Отключается
    в Настройки → Фильтрация. Тумблер + пояснения добавлены в UI.
  - Затрагивает `core/strategy_builder._compute_list_flags`,
    `core/config_manager.DEFAULT_CONFIG`. Сканер (явный `hostlist_path` под
    цель) и единый слой `nfqws.unified_hostlist` не изменились. Следствие:
    z2k-пресеты (`всё-в-одном`, smart, rkn/yt/gv, discord/yt_quic) теперь
    работают на youtube/discord/всём из коробки, Discord-voice больше не
    глохнет от подставленного hostlist.
- **Прогресс-бар при тесте серверов И сборке пула.** Тестер прокси
  (`core/proxy_tester.py`) сообщает прогресс по фазам (TCP-отсев → e2e
  через движок). Сборка пула (`server_pool.refresh_pool`) переведена в
  асинхронный job с прогрессом по фазам **скачивание источников →
  проверка серверов → сборка конфига** (`/api/singbox/pool/refresh`
  стартует job, `/api/singbox/pool/refresh/status` отдаёт прогресс). UI
  (sing-box → Пул серверов) рисует полосу прогресса с процентом и для
  «Тест серверов», и для «Собрать пул сейчас».
- **Бэкап/восстановление**: восстановление настроек теперь
  переконфигурирует фоновые задачи (подписки, пул серверов, курируемые
  списки, мониторинг единого слоя) — изменения подхватываются без
  перезапуска GUI. Бэкап покрывает весь `settings.json` (включая
  подписки/пул/именованные списки/маршруты единого слоя — проверено).

### Добавлено
- **Таймаут `awg setconf` конфигурируем** (`awg.setconf_timeout_sec`,
  по умолчанию 15 с, диапазон 5..120) — `core/awg_manager.py::_setconf_timeout`.
  На очень слабом CPU или при необходимости подтвердить «демон завис, а не
  не успел» можно поднять. Важно: применение полей через UAPI — операция на
  миллисекунды, поэтому таймаут >15 с почти всегда означает настоящий
  deadlock демона (нет ответа вовсе), а не нехватку времени.

- **«cannot import name 'save_config'» при включении DNS-перехвата — и
  молчаливая потеря настроек DoH/автостарта sing-box**
  (`core/config_manager.py`; отчёт с Keenetic). Докстринг
  `config_manager` обещал модульную `save_config()`, но существовал
  только метод `ConfigManager.save()`. На задокументированный API

  включении перехвата), `doh_resolver.set_settings` и
  `singbox_autostart._save_settings` — у последних двух импорт стоял в

  сохранялись** с самого появления этих модулей. Добавлена модульная
  `save_config()` (делегирует глобальному менеджеру), докстринг
  приведён к реальному API. Регрессионные тесты —
  `test_dns_intercept.py::TestSetEnabled`,
  `test_doh_resolver.py::TestSetSettingsSaves`.
- **Доменное правило больше не исчезает молча, когда set-путь не

## v0.19.29 — Routing: форвард LAN→туннель резался FORWARD-policy DROP + понятная ошибка dnsmasq

### Исправлено
- **Маршрутизация устройств/CIDR не работала с устройств за роутером —
  пакеты уходили, ответов не было.** По диагностике видно: MASQUERADE
  на AWG-интерфейс уже корректный и первый в POSTROUTING (src
  переписывается на туннельный), но `FORWARD`-политика на роутере =
  `DROP`, а штатный firewall (Keenetic ndm) НЕ знает наш AWG-интерфейс —
  поэтому форвард `LAN → WARPv2_xx` проваливался в DROP, и реальный
  трафик клиента в туннель не попадал (в счётчике — только overhead
  хендшейка ~184 B). С самого роутера работало, т.к. это OUTPUT, а не
  FORWARD. Теперь для AWG-интерфейса в начало `FORWARD` добавляется
  `ACCEPT` в обе стороны (`-i`/`-o`), снимается вместе с masquerade,
  когда на интерфейс не осталось правил. MASQUERADE и FORWARD-accept для
  всех типов правил (cidr/device/domain) теперь идут через общий helper.
- **dnsmasq на Keenetic не стартовал — теперь видно почему.** Init-скрипт
  `/opt/etc/init.d/S56dnsmasq` отрабатывал, но dnsmasq сразу падал
  (pid=0). Причина почти всегда — :53 уже занят штатным DNS роутера, и
  Entware-dnsmasq не может его занять. GUI теперь проверяет, кто слушает
  :53 (через /proc/net/{tcp,udp}), прогоняет `dnsmasq --test` и пишет
  внятную причину в лог/ответ вместо «ошибки ?». Полностью автоматически
  поднять dnsmasq на занятом :53 нельзя — нужна ручная настройка на
  свободном порту; для обхода по доменам без dnsmasq используйте CIDR.

## v0.19.25 — Keenetic: верное определение MIPS-архитектуры (mipsel vs mips) + видимые ошибки запуска

### Исправлено
- **На MIPS-роутерах ставилась неверная архитектура → «Exec format

## v0.19.23 — Domain-routing: set был пуст — pre-population + v6-set в директиве + user=root

### Исправлено
- **nft/ipset set оставался пустым → трафик не маркировался.**
  Диагностика v0.19.22 показала: chain output `type route` ✓,
  MASQUERADE ✓, `ip rule fwmark` ✓, resolv.conf → 127.0.0.1 ✓,
  dnsmasq запущен с managed-директивой ✓ — но
  `set awgr_domain_… { type ipv4_addr }` **пустой**. Причины три,
  и пофикшены все:
  1. **В директиве `nftset=` был только v4-set.** 2ip.ru (как и
     большинство сайтов) отдаёт AAAA, браузеры ходят по IPv6 первым.
     v6-set `awgr_…6` нигде не упоминался — dnsmasq в него не писал.
     Теперь эмитим оба set'а одной директивой:
     `nftset=/dom/inet#awg_routing#set/inet#awg_routing#set6`.
  2. **Браузеры с DoH (Firefox/Chrome) идут мимо dnsmasq.** dnsmasq
     заполняет set ТОЛЬКО когда видит DNS-query, а DoH резолвит
     через Cloudflare напрямую — query до dnsmasq не доходит, set
     пуст. Добавил **pre-population**: при apply domain-правила сами
     резолвим домены (v4+v6) и кладём IP в set через `nft add
     element` / `ipset add`. Работает «на сейчас» независимо от того,
     каким резолвером пользуется приложение.
  3. **dnsmasq на Debian дропает CAP_NET_ADMIN.** Без него запись в
     nftset тихо проваливается. Дефолтный `/etc/dnsmasq.conf` теперь
     создаётся с `user=root`/`group=root`; для уже настроенных систем
     auto-setup ретроактивно дописывает `user=root` и рестартует
     dnsmasq (SIGHUP не применяет смену user). В UI появляется кнопка
     «Применить обновления dnsmasq-конфига», когда есть отложенные
     шаги.

## v0.19.21 — Domain-routing наконец работает: nft output как type=route, а не filter

### Исправлено
- **Domain-routing продолжал не работать после v0.19.20.** Диагностика
  показала: `ip rule fwmark 0x… lookup 141` стоит, default-маршрут в
  таблице 141 ведёт на AWG, dnsmasq заполняет nftset, OUTPUT mangle
  ставит метку — а пакет всё равно уходит через WAN. handshake AWG
  идёт (peer показывает свежий handshake), но **реального трафика
  нет** — только keepalive.
  Корень: цепочка `output` в `inet awg_routing` создавалась как
  `type filter hook output priority mangle`. **`type filter` не
  триггерит ререйт** после изменения mark — ядро отправляет пакет по

  fwmark` не успевает. Нужен `type route hook output` — это
  единственный nft-тип, который сигнализирует kernel'у пере-выбрать
  маршрут, если mark поменялся в хуке (документация nftables:
  «type route: re-route the packet if any field affecting routing
  is modified»). prerouting может остаться `type filter` — там
  routing decision происходит ПОСЛЕ хука.
  Починка: создаём output с `type route`. На uplevel обнаруживаем
  таблицу со старым `type filter` и пересоздаём её. Соседние
  domain-правила, которые там жили, переразлагаем автоматически.
  Без этого фикса MASQUERADE из 0.19.20 не помогал — пакет до AWG
  вообще не доходил.

## v0.19.15 — AWG up больше НЕ становится default-шлюзом

### Исправлено
- **AWG up при `AllowedIPs = 0.0.0.0/0` принудительно загонял весь
  трафик системы в туннель**, даже когда в «Routing» (cidr/domain/
  device) не было ни одного правила — это полностью противоречит
  семантике селективного маршрутизатора, ради которого GUI и сделан.
  Симптом у пользователя: «просто стартую демон без правил — инет
  пропадает». Под капотом было копипастой схемы `wg-quick`:
  `awg set fwmark` + `ip rule add not fwmark X table X` +
  `suppress_prefixlength 0` + pin'я peer-endpoint'а через main, чтобы
  тот сам себя не заворачивал. Эта же схема требовала, чтобы туннель
  был исправен; а на полу-сломанном (handshake идёт, data сервер
  дропает) система оставалась без интернета вовсе.

  Теперь `_do_up` кладёт `default dev <iface>` и все `AllowedIPs` -
  маршруты **ТОЛЬКО в табличку туннеля `<table_id_for(iface)>`**.
  `main` не трогаем вообще. Туннель просто «доступен» через свою
  таблицу, а кто туда направит трафик — решают исключительно правила
  из секции Routing. Пустой список правил = весь трафик идёт мимо
  туннеля как обычно.

  Удалены `_add_default_via` и `_pin_peer_endpoints` — их роль теперь
  выполняет один прямой `ip route add … table <T>`. Teardown
  упрощён до `ip route flush table <T>` для обоих семейств; старые
  routes.json (от ≤ 0.19.14) подчищаются по-старому для совместимости.

### Исправлено
- **AWG-tunnel handshake проходил, но данные сервер дропал** —
  `core/awg_config.py`. Кодовая база знала только первое поколение

  show`, разбор `interface_state` (с fwmark/handshake/RX-TX), полный

### Исправлено
- **AWG up при AllowedIPs=0/0 ронял весь инет даже при пустом списке
  selective routing** — `core/awg_manager.py:_add_default_via`. До правки

## v0.13.3 — Привязка firewall к WAN-интерфейсам

### Исправлено
- **Firewall не привязывался к WAN-интерфейсам** — правила iptables/nftables применялись без `-o $IFACE_WAN`, перехватывая трафик на всех интерфейсах. Теперь `firewall.py` читает `interfaces.wan` и `interfaces.wan6` из конфига и создаёт правила с привязкой к конкретным интерфейсам (как в zapret2 `_fw_nfqws_post4`/`_fw_nfqws_post6`)

- **Авто-определение WAN при старте firewall** — если `interfaces.wan` пуст, определяется по `/proc/net/route` (fallback на `ip route`)
- **Fallback WAN6 → WAN** — если `interfaces.wan6` не задан и не определён, используется значение WAN (как `IFACE_WAN6` в zapret2)
- **Множественные WAN-интерфейсы** — для каждого интерфейса создаётся отдельное правило в iptables (`-o eth0`, `-o eth1`); в nftables используется `oifname { "eth0", "eth1" }`
- **Очистка ip6tables** — при снятии правил теперь удаляются и правила ip6tables
