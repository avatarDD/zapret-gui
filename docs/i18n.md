# Язык интерфейса: русский и английский

Русский — основной язык интерфейса и язык по умолчанию. Английский
включается кнопкой **EN** в подвале бокового меню (рядом с темой) или в
**Настройки → Язык интерфейса**. Выбор хранится в этом браузере
(`localStorage['zapret-gui-lang']`, как и тема); после переключения
страница перезагружается. Если на странице есть несохранённые правки
(настройки, редакторы lua, hostlist, ipset, hosts, маршрутов), сначала
спрашивается подтверждение: страница настроек ставит свой страж через
`i18n.setSwitchGuard(fn)`, у редакторов видна метка `.lists-unsaved` /
`#ru-dirty`.

## Как устроено

Интерфейс написан по-русски прямо в шаблонах страниц (около 5600 строк),
поэтому перевод сделан словарём «русская фраза → английская», а не
переписыванием всех строк на ключи.

| Файл | Что делает |
|---|---|
| `web/js/utils/i18n.js` | язык, переводчик DOM, ключевой API `_t()` |
| `web/js/i18n/en.text.js` | словарь фраз `i18n_en_text` (генерируется и правится вручную) |
| `web/js/i18n/ru.js`, `en.js` | ключевой словарь для `_t('mcp.warn.token')` — длинные тексты |
| `web/js/i18n/en.server.js` | словарь сообщений сервера `i18n_en_server`: ошибки API, логи, итоги проверок |
| `tools/i18n_extract.js` | сбор русских строк из `web/`, проверка покрытия |
| `tools/i18n_extract_server.py` | сбор русских сообщений из `api/`, `core/`, `app.py`, проверка покрытия |
| `tests/test_i18n.js`, `tests/test_i18n_server.py` | покрытие словарей и поведение переводчика |

В русском режиме словарь фраз не загружается и DOM не трогается.

В английском режиме `i18n.js` ещё во время разбора `index.html`
подгружает `en.text.js` и `en.server.js` (через `document.write`, до
скриптов страниц; адреса с `?v=` берутся из `<link rel="x-i18n-en-text">`
и `<link rel="x-i18n-en-server">` в `index.html`). Оба словаря сливаются в
один индекс; при совпадении ключей побеждает перевод из `en.text.js`.
После загрузки:

- переводит текстовые узлы и атрибуты `title`, `placeholder`,
  `aria-label`, `alt`, `data-tip`, `data-label`, `value` у кнопок и `label`
  у `optgroup`;
- следит за изменениями DOM (`MutationObserver`) и переводит всё, что
  страницы дорисовывают;
- переводит тексты `alert` / `confirm` / `prompt`;
- ставит `<html lang="en">`; `i18n.locale()` отдаёт `en-US` для
  `toLocaleString`.

Не переводится содержимое `textarea`, `pre`, `code`, `script`, `style`,
редактируемых областей и элементов с `translate="no"` или
`data-no-i18n`. Так помечены, например, строки логов, правила firewall
и превью команды: это вывод программ, а не интерфейс. Строки журнала
(`.log-message` на страницах «Логи», «Главная», «Управление») страница
переводит сама, до подсветки: `i18n.translateText(entry.message)`, так что
сообщения сервера показываются по-английски, а вывод движков, пути и
имена остаются как есть. Поиск на странице «Логи» идёт и по исходному, и
по показанному тексту. Свою
подпись внутри такого блока («Загрузка...») переводи явно:
`i18n.translateText('Загрузка...')` (в русском режиме возвращает строку
как есть).

### Сопоставление фраз

1. **Точное совпадение** после схлопывания пробелов. Пробелы по краям
   узла сохраняются. Строка со строчной буквы находит ключ с заглавной.
2. **Шаблоны.** Ключ `Найдено {0} доменов` сопоставляется с
   `Найдено 12 доменов`; в переводе места подстановки можно
   переставлять (`{1} из {0}` → `{1} of {0}`). Значение подстановки,
   если в нём есть кириллица, переводится тем же словарём, кроме
   значения в кавычках (`Конфиг «{0}» не найден`): это имя, которое дал
   пользователь. При шаблонах одинаковой длины сначала пробуются ключи
   `en.text.js`.
3. **Куски через разделители.** Сначала крупные куски через ` — `,
   ` · `, ` | ` (`Исключения (не обрабатываются) — netrogat.txt`; хвост,
   который код дописывает с тире, хранится в словаре с ним же:
   `— не сразу`), затем мелкие: `AmneziaWG · Конфиги`,
   `Сайты по доменам:`, `Что делает: А + Б` переводятся по частям, если
   переведена каждая часть с кириллицей.

Если перевод неполный (часть русского осталась), он берётся, только когда
переведённая часть заметно длиннее оставшейся: метка переводится, данные
остаются как есть, а каши из полуанглийских фраз не получается.

Текст длиннее 600 символов ищется только точным совпадением (и по
строкам, если он многострочный): шаблоны на нём слишком дороги.

Не найденные фразы копятся в `i18n.missing()` — удобно смотреть в
консоли браузера.

## Что не переводится

- данные пользователя и вывод программ (логи, конфиги, списки);
- тексты каталогов стратегий и готовых списков (`catalogs/`, заголовки
  `@title` в файлах списков);
- ответы инструментов MCP (`core/mcp/`, `api/mcp.py`: их читает модель)
  и CLI (`core/cli.py`); список — `EXCLUDE` в
  `tools/i18n_extract_server.py`;
- docstring'и, строки в сравнениях и регулярных выражениях, тексты
  генерируемых скриптов и конфигов;
- вывод сторонних программ (nfqws2, sing-box, mihomo и др.) в логах.

## Новая строка в интерфейсе

Пишешь в шаблоне по-русски, как и раньше, затем:

```sh
node tools/i18n_extract.js --missing          # JSON недостающих ключей
node tools/i18n_extract.js --check            # 0 недостающих = успех
```

и добавляешь перевод в `web/js/i18n/en.text.js` (одна строка
`"русская фраза": "English",`). Места подстановки `{0}`, `{1}` в ключе
и переводе должны совпадать — это проверяют `--check` и
`tests/test_i18n.js`.

Ключ — ровно то, что показал `--missing`: склейки `'Найдено ' + n + '
доменов'` и `${n}` в шаблонных строках становятся `{0}`, текст между
тегами — отдельными ключами. Чтобы фраза переводилась целиком, держи её
в одном текстовом узле: `<b>` посреди предложения режет её на куски.

Прочие режимы инструмента: `--stats` (сколько ключей и сколько
переведено), `--unused` (ключи словаря, которых нет в коде; их может
давать сервер, удалять с оглядкой).

## Новое сообщение сервера

Сервер по-прежнему пишет по-русски (в логах, ответах API, итогах
проверок); перевод делает браузер. Добавил или поменял русскую строку в
`api/`, `core/` или `app.py`:

```sh
python3 tools/i18n_extract_server.py --missing   # JSON недостающих ключей
python3 tools/i18n_extract_server.py --check     # 0 недостающих = успех
```

и добавь перевод в `web/js/i18n/en.server.js` (файл сортирован по
ключам; можно править руками или через `save_dict` из того же модуля).
Ключи строятся так же, как для страниц: `"Ошибка записи %s: %s" % (a, b)`,
`f"Запущен {name}"`, `"…{}".format(x)` и склейки через `+` становятся
`{0}`, `{1}`. Нелитеральное слагаемое (`x if c else ' (текст)'`) — тоже
`{0}`, а его собственный текст получает отдельный ключ: переводчик
переведёт подстановку тем же словарём. Покрытие проверяют `--check`, `tests/test_i18n_server.py` и
`tests/test_i18n.js`. Режимы `--stats` и `--unused` — как у
`i18n_extract.js`.

Числительные: у русских форм (`1 запись`, `2 записи`, `5 записей`) свои
ключи `{0} запись` и т.д.

Для длинных текстов в новом коде можно по-прежнему использовать ключи:
`_t('mcp.warn.token')` со строками в `ru.js` и `en.js`. Если ключа нет в
`en.js`, в английском режиме он ищется в словаре фраз.
