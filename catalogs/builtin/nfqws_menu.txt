# ─────────────────────────────────────────────────────────────
#  Полные пресеты из rndnaame/nfqws-menu
#
#  Источник: github.com/rndnaame/nfqws-menu (strategies/nfqws2, коммит 424708d).
#  21 стратегия — порты zapret-discord-youtube 1.10.3 (Flowseal, winws1)
#  на nfqws2 под пакет nfqws2-keenetic, плюс личные конфиги участников
#  чата (MartinBacker, Uvvi2, eduncey, hardcorp74, krushaaa) и alt4_mod.
#
#  Перенос в наш формат:
#    • профили собраны в порядке пакета: NFQWS_ARGS_CUSTOM → UDP → QUIC →
#      HTTPS. Специфичные профили (discord.media, список Google) идут
#      первыми, иначе их перехватил бы общий профиль 80,443;
#    • NFQWS_EXTRA_ARGS (режим list/auto/all) и NFQWS_ARGS_IPSET у нас —
#      «Фильтрация» в GUI, поэтому ни хостлистов режима, ни ipset-копий
#      HTTPS/QUIC-профилей в пресетах нет;
#    • google.list из nfqws-menu (list-google бандла + play.google.com,
#      fonts.googleapis.com, www.gstatic.com, google.ru, youtube.googleapis.com)
#      вписан как --hostlist-domains — пресет не зависит от файла;
#    • --blob= не нужны: имена приведены к нашему реестру по содержимому
#      файлов. stun_fake/stun2_fake → stun/stun2, tls_clienthello_sochi_park
#      → tls_sochi, а tls_max nfqws-menu (664 байта) — это ClientHello
#      www.onetrust.com, не наш tls_max (max.ru, 193 байта): отсюда
#      tls_clienthello_www_onetrust_com, иначе seqovl=664 перекрывал бы
#      чужим узором. discord_udp/game_udp nfqws-menu (QUIC Initial
#      steamcommunity.com/4pda.to) побайтово совпадают с нашими
#      ACTIVE_DISCORD_UDP/ACTIVE_GAME_UDP. Новые блобы quic_5ka,
#      quic_lordfilm, tls_lordfilm, quic_dbankcloud — в import/bin;
#    • игровой фильтр (в оригиналах закомментирован) не переносится;
#    • профили по ipset-спискам авторов (ipset_do, ipset_cf_full,
#      ipset_amazon, ipset_ovh, ipset_as_*) убраны: этих списков у нас нет;
#    • UDP-шаг «fake:repeats=6:strategy=N» (MartinBacker, дефолт пакета) —
#      с blob=fake_default_udp: без blob= lua бросает «fake: 'blob' arg
#      required», и circular через раз попадал на пустой шаг;
#    • нулевой фейк «tcp_ack=-66000» (MartinBacker, Uvvi2, дефолт) — с
#      tcp_ts_up: nfqws2 не поднимает метку TCP первой опцией, как nfqws1,
#      и Linux-сервер отбрасывает такой фейк через раз.
#
#  ⚠️ ts-фулинг (tcp_ts=…:tcp_ts_up) работает, только если клиент шлёт
#  TCP timestamps; в Windows они выключены по умолчанию
#  (netsh interface tcp set global timestamps=enabled).
#  ⚠️ Порты: 2053,2083,2087,2096,8443 (discord.media), 1984/5222 (MTProto,
#  XMPP) и UDP 19294-19344,50000-50100 должны попасть в перехват. Это
#  делает nfqws.ports_from_strategy (по умолчанию да); без неё — дописать
#  в «Настройки → nfqws2 → TCP/UDP-порты», иначе профиль не увидит ни
#  одного пакета.
# ─────────────────────────────────────────────────────────────
